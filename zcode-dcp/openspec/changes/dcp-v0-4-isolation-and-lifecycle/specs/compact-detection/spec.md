# Spec Delta

## Purpose

通过相邻两轮用量骤降检测内核压缩事件，实现压缩统计、窗口自动校准与压缩后即时召回，弥补内核不暴露压缩 hook 的缺口。

## ADDED Requirements

### Requirement: 骤降判定压缩发生

当相邻两次计量之间占用 token 数下降超过 40%（即本次 < 上次的 60%）且上次值大于 20000 时，插件 SHALL 判定发生了一次压缩，并记录压缩事件（时间、压缩前后 token、节省量，保留最近 20 条）。

#### Scenario: 内核压缩后检出

- **WHEN** 上轮计量 900000 tokens，本轮读到 120000 tokens
- **THEN** 记录一条压缩事件，节省量为 780000

#### Scenario: 正常回落不误判

- **WHEN** 两轮之间用量小幅下降（如 500000 → 480000）
- **THEN** 不记录压缩事件

### Requirement: 窗口自动校准

每次检出压缩时，插件 SHALL 以压缩前用量加 34000 推算观测窗口并保留最近 5 个观测；当存在不少于 2 个观测且用户未显式配置窗口时，SHALL 取中位数作为生效窗口，并在占用查询中标注窗口来源。

#### Scenario: 未配置时校准生效

- **WHEN** 用户未在插件配置中设置窗口，校准观测已有 2 条（934000、930000）
- **THEN** 生效窗口为 932000，占用查询的 windowSource 为 calibrated

#### Scenario: 显式配置优先

- **WHEN** 用户已显式配置窗口为 500000
- **THEN** 校准值不生效，windowSource 为 config

### Requirement: 压缩后即时召回

在用户消息提交时检出压缩发生的，插件 SHALL 在该轮开始前注入召回内容：压缩提示（节省量）、当前占用、归档索引（有归档时）与检索/取回说明。

#### Scenario: prompt 检出压缩即召回

- **WHEN** 用户发消息触发的计量检出压缩且存在归档块
- **THEN** 该轮开始前出现含归档索引的召回注入
